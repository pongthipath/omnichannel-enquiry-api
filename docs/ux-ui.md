# UX/UI — Omnichannel Customer Enquiry

> ผู้ออกแบบ: web-uxui (skill: `frontend-design`, `ui-ux-pro-max`, `mobile-app-ui-design`) · อ้างอิง [`design.md`](design.md) · 2026-09-22

## 1. Design direction

**"Operations console ที่สงบ"** — เครื่องมือทำงานของทีม CS บริษัทจัดจำหน่ายอาหาร ที่ต้องเปิดทั้งวัน ข้อมูลแน่น แต่ไม่เครียด

| | |
|---|---|
| ผู้ใช้ | ลูกค้า B2B (เจ้าของร้าน/ฝ่ายจัดซื้อ ร้านอาหาร โรงแรม) ใช้มือถือระหว่างทำงาน · agent 7 แผนกใช้จอคอมทั้งวัน |
| ทิศทาง | utilitarian + editorial เล็กน้อย: navy เข้ม, ฟ้าเป็น action, เส้นบาง, ความหนาแน่นสูงฝั่ง agent / ใหญ่ อ่านง่าย ฝั่งลูกค้า |
| **จุดเด่นที่จำได้ 1 อย่าง** | **SLA timer** — แถบเวลาที่หดลงบนทุกแถวและหัว thread บอก "เหลือ 1:24 ชม." / "เกิน SLA 12 นาที" เป็นภาษาคน |
| จุดเด่นรอง | **channel badge ต่อข้อความ** (Web / LINE / FB / App / Phone) ทำให้เห็นการคุยข้ามช่องทางใน thread เดียว |
| สิ่งที่ตั้งใจ **ไม่** ทำ | gradient ม่วง-ชมพู, glassmorphism, การ์ดเงาหนา, emoji แทน icon, animation ประดับ |
| ที่มา | ui-ux-pro-max `--design-system` (B2B helpdesk, density 8, motion 3) → style *Accessible & Ethical*, palette navy+blue; ตัด font Calistoga ออก (display font ไม่เหมาะกับจอที่ข้อมูลแน่น) และเปลี่ยนเป็นฟอนต์ที่รองรับไทย |

## 2. User flows

### Customer — สร้าง enquiry (online/offline ทางเดียวกัน) — story §4, §13
```
[C1 รายการ] → แตะ "+ สร้าง" → [C3 ฟอร์ม]
  1 เลือกประเภท (grid 7 ช่อง) → 2 (ถ้าประเภทต้องใช้สินค้า) ค้นหา/เลือกสินค้า
  → 3 หัวเรื่อง + รายละเอียด + ความเร่งด่วน → 4 แนบรูป/ไฟล์ (optional)
  → [ส่ง] → กลับ C1: การ์ดใหม่อยู่บนสุด
       online : "กำลังส่ง…" → "ส่งแล้ว · ENQ-2026-000123"
       offline: "รอส่ง · จะส่งอัตโนมัติเมื่อออนไลน์" + แถบบนสุด "ออฟไลน์ · รอส่ง 3 รายการ"
```
3–4 แตะจากหน้ารายการถึงส่งสำเร็จ (ไม่นับการพิมพ์) · ฟอร์มยาวหน้าเดียวแบ่ง section (ไม่ใช่ wizard หลายหน้า) เพื่อให้ย้อนแก้ง่ายและเก็บ draft ได้

### Customer — ติดตาม/ตอบ — §4, §10
`[C1] → แตะการ์ด → [C4 thread]` เห็นสถานะ + timeline + ข้อความพร้อม delivery state → พิมพ์ตอบ / แนบ → ข้อความขึ้นทันทีสถานะ `pending` แล้วเปลี่ยนเป็น ✓ / ✓✓

### Agent — รับเรื่องจนปิด — §7
```
[A1 Dashboard] → แตะตัวเลข "SLA เกิน 3" → [A2 Inbox กรองไว้แล้ว]
→ เลือกแถว → [A3 workspace: thread กลาง | Customer 360 ขวา]
→ "รับเรื่อง" (ASSIGNED→IN_PROGRESS) → ตอบ → "รอลูกค้า" / "ส่งต่อแผนก" (ConfirmModal + เหตุผล) / "แก้ไขแล้ว"
```

### Omnichannel demo — §11
`[A5 Simulator]` เลือก channel=Website, ลูกค้า A → ส่ง "Do you have French Butter?" → toast "สร้าง ENQ-…124" + ลิงก์ → เปลี่ยน channel=LINE → ส่ง "Any update about my previous enquiry?" → toast "ต่อเข้า ENQ-…124 (Web → LINE)" → เปิด A3 เห็นสอง badge ใน thread เดียว

| `muted` / `muted-foreground` | `#E8ECF1` / `#475569` | `#1E293B` / `#94A3B8` | ข้อความรอง |

**SLA**: ปกติ `#15803D` · ใกล้หมด (<25%) `#B45309` · เกิน `#B91C1C` + ไอคอน + ข้อความ "เกิน SLA"

### Typography
- **v9 (user แจ้งว่าแบบเดิมอ่านยาก):** เปลี่ยนจาก IBM Plex Sans Thai (ไม่มีหัว) เป็น **Noto Sans Thai Looped** (ไทยมีหัว อ่านง่ายบนจอ โดยเฉพาะตัวเล็กและข้อความยาว) คู่กับ **Noto Sans** สำหรับอักษรละติน (family เดียวกัน น้ำหนักเส้นเข้ากัน) · stack: `"Noto Sans", "Noto Sans Thai Looped", "Noto Sans Thai", system-ui, sans-serif`
- **IBM Plex Mono** ใช้เฉพาะตัวเลข/รหัสล้วน (ENQ id, เวลา SLA, รหัสสินค้า) ให้ตัวเลขตรงคอลัมน์ · ข้อความไทยไม่ใช้ mono (stack ของ mono fallback ไป Noto Sans Thai Looped)
- ไม่ใช้ตัวพิมพ์ใหญ่ + ระยะห่างตัวอักษรกว้างกับหัวข้อเล็ก (eyebrow) เพราะทำให้ภาษาไทยอ่านยาก
- scale (px): **ตัวเล็กสุด 12** (caption/badge) · 15 body-sm (ตาราง staff) · 16 body (ลูกค้าขั้นต่ำ) · 18 · 22 · 28 · line-height **1.7** สำหรับเนื้อความไทย (มีวรรณยุกต์และสระบน-ล่าง) · 1.3 สำหรับหัวข้อ
- ทางเลือกถ้าอยากได้โทนอื่น: **Sarabun** (มีหัว ทางการกว่า) · **Anuphan** / **Noto Sans Thai** (ไม่มีหัว ทันสมัย เหมาะกับหัวข้อ)

### Spacing / radius / elevation / motion
- spacing 4-pt: 4 8 12 16 24 32 48 · staff row สูง 64 (ขยายตามตัวหนังสือ v9) · touch target ≥ 44
- radius: 6 (input/badge) · 10 (card) · 16 (sheet)
- elevation: ใช้เส้นขอบแทนเงา; เงาเฉพาะ modal/sheet
- motion: 150–200ms `ease-out` สำหรับ state, 250ms สำหรับ sheet; ข้อความใหม่ fade+slide 8px; SLA bar เปลี่ยนความยาวแบบ linear; `prefers-reduced-motion` → ตัด slide เหลือ fade

## อัปเดต v8 — Chat list ของลูกค้า + ค้นหา

Inbox มี 2 มุมมองในแผงรายการเดียวกัน (สลับได้ จำค่าใน `ui_preferences`):
- **เรื่อง** — 1 แถว = 1 enquiry (แบบเดิม)
- **แชทลูกค้า** — 1 แถว = 1 ลูกค้า รวมทุกเรื่องและทุกช่องทางของลูกค้าคนนั้น เรียงตามข้อความล่าสุด (แบบ LINE OA chat list)

### A9 — รายการแชทลูกค้า
```
[ เรื่อง | แชทลูกค้า ✓ ]
[ค้นหาชื่อร้าน ผู้ติดต่อ เบอร์ อีเมล รหัส หรือข้อความ…        ]
[ช่องทาง ▾] [มีเรื่องเปิด] [ยังไม่อ่าน] [ยังไม่ระบุตัวตน]
──────────────────────────────────────────────────────
 (BB) Bangkok Bistro Co.                    11:01   (2)   ← (2) = ข้อความลูกค้าที่ยังไม่มีใครอ่าน
      LINE · "ส่งให้แล้วค่ะ"                               
      [LINE][App][Web]  เรื่องเปิด 2 · เกิน SLA 1           ← SLA ที่แย่ที่สุดของลูกค้าคนนั้น
```

- **1 ลูกค้า = 1 แถวเสมอ** ไม่ว่าจะมีกี่เรื่อง กี่ช่องทาง · ข้อความใหม่เข้ามา → แถวนั้นขึ้นบนสุด (ย้ายแถวเดิม ไม่เพิ่มแถวใหม่)
- เห็นเฉพาะลูกค้าที่มีเรื่องอยู่ในขอบเขตของตัวเอง · คนที่มี `inbox.scope.all` เห็นลูกค้าทั้งหมด · preview/ตัวเลขนับเฉพาะเรื่องที่เห็น
- ตัวย่อชื่อในวงกลม (ไม่ใช้รูปโปรไฟล์จากช่องทางเป็นค่าเริ่ม) · placeholder มีป้าย "ยังไม่ระบุตัวตน"

### ค้นหา
- ช่องเดียวค้นได้ทั้ง **ข้อมูลลูกค้า** (ชื่อร้าน, ผู้ติดต่อ, เบอร์บางส่วน, อีเมล, รหัสลูกค้า, ชื่อในช่องทาง เช่นชื่อ LINE) และ **เนื้อหาข้อความ** · ค้นเมื่อหยุดพิมพ์ 300ms · อย่างน้อย 2 ตัวอักษร

- ลูกค้าคนเดียวเจอหลายข้อความ → ยังเป็น 1 แถว แสดงข้อความที่ตรงล่าสุด + "และอีก 4 ข้อความ"
- ไม่พบ: "ไม่พบลูกค้าหรือข้อความที่ตรงกับ ‘{{q}}’" + ปุ่มล้างตัวกรอง

### 2) แท็ก


- combobox พิมพ์ค้น + เลือกได้หลายอัน (keyboard: ↑↓ เลือก, Enter ติด, Backspace ถอดอันสุดท้าย) · แสดงเฉพาะแท็กที่ scope ตรง (แชท/ลูกค้า)
- ติด/ถอดแล้วบันทึกทันที + ปุ่มเลิกทำใน toast · แชทอื่นที่เปิดเรื่องเดียวกันเห็นเปลี่ยนแบบ realtime
- ในรายการ (ทั้ง "เรื่อง" และ "แชทลูกค้า"): แสดงแท็กสูงสุด 2 อัน + "+N" · ตัวกรอง **แท็ก ▾** (เลือกหลายอัน, เงื่อนไข "มีแท็กใดแท็กหนึ่ง")
- ป้ายแท็ก = จุดสี + ชื่อ บนพื้นสีอ่อน (ไม่พึ่งสีอย่างเดียว) · แท็กที่ปิดใช้งานแล้วแสดงจาง + tooltip "ปิดใช้งานแล้ว"

### 3) Login

**L1 — เข้าสู่ระบบ (ลูกค้า — แอป/เว็บ `/login`)**
```
┌──────────────────────────────┐
│  FoodLink                    │
│  เข้าสู่ระบบ                  │
│  อีเมล                        │
│  [malee@bkkbistro.co      ]  │
│  รหัสผ่าน                     │
│  [••••••••••          แสดง]  │
│  [✓] จดจำฉันไว้ในเครื่องนี้      │
│  [        เข้าสู่ระบบ        ]  │
│  ลืมรหัสผ่าน?                 │
│  ─────────────────────────   │
│  เข้าสู่ระบบสำหรับพนักงาน →     │
└──────────────────────────────┘
```
**L2 — เข้าสู่ระบบพนักงาน (web `/staff/login`)**: ฟอร์มเดียวกัน หัวเรื่อง "สำหรับพนักงาน" · จอกว้างแบ่งซ้าย (ฟอร์ม) / ขวา (พื้นสี navy + ข้อความสั้น "ระบบรับเรื่องลูกค้า") · ลิงก์กลับ "ฉันเป็นลูกค้า"

- ปุ่ม **แสดง/ซ่อนรหัสผ่าน** · รองรับ password manager (`autocomplete="username"` / `"current-password"`, native `textContentType`) · Enter ส่งฟอร์ม
- กดแล้วปุ่มเป็น "กำลังเข้าสู่ระบบ…" (disable กันกดซ้ำ)
- ผิด: ข้อความเดียว "อีเมลหรือรหัสผ่านไม่ถูกต้อง" ใต้ฟอร์ม (ไม่บอกว่าอีเมลมีอยู่ไหม) · focus กลับช่องรหัสผ่าน
- ถูกล็อก: "ลองผิดหลายครั้งเกินไป ลองใหม่ได้ในอีก 14 นาที หรือตั้งรหัสผ่านใหม่" + ลิงก์ลืมรหัส
- บัญชี staff ถูกปิด: "บัญชีนี้ถูกปิดใช้งาน ติดต่อผู้ดูแลระบบ"
- ออฟไลน์ (แอปลูกค้า): ถ้าเคย login และ session ยังไม่หมด → เข้าได้และใช้ offline ได้ตามเดิม · ถ้ายังไม่เคย → "ต้องเชื่อมต่ออินเทอร์เน็ตเพื่อเข้าสู่ระบบครั้งแรก"
- login สำเร็จ → ไปหน้าที่ตั้งใจจะเข้าก่อนถูกพามา login (หรือหน้าแรกตามสิทธิ์: staff ที่ไม่มี `dashboard.page.view` → Inbox)

**L3 — ลืมรหัสผ่าน:** ใส่อีเมล → "ถ้ามีบัญชีนี้ เราได้ส่งลิงก์ตั้งรหัสผ่านไปที่อีเมลแล้ว (ลิงก์ใช้ได้ 30 นาที)" (ข้อความเดียวกันทุกกรณี) + ส่งอีกครั้งได้หลัง 60 วินาที

**L4 — ตั้งรหัสผ่าน (จากลิงก์ reset หรือคำเชิญ):** รหัสใหม่ + ยืนยัน · แถบบอกความยาว/เงื่อนไขแบบข้อความ ("อย่างน้อย 10 ตัวอักษร ✓", "ไม่ใช่รหัสที่คาดเดาง่าย ✓") · ลิงก์หมดอายุ → "ลิงก์นี้หมดอายุแล้ว" + ปุ่มขอลิงก์ใหม่ · สำเร็จ → "ตั้งรหัสผ่านแล้ว ออกจากระบบทุกอุปกรณ์เรียบร้อย" → ไปหน้า login · ลิงก์เปิดในแอปได้ (deep link)

**L5 — ความปลอดภัยบัญชี (เมนูโปรไฟล์):** เปลี่ยนรหัสผ่าน (ต้องใส่รหัสเดิม) · อุปกรณ์ที่เข้าสู่ระบบอยู่ (ชื่ออุปกรณ์/เบราว์เซอร์, เวลาใช้ล่าสุด, "เครื่องนี้") + "ออกจากระบบ" รายเครื่อง + "ออกจากระบบทุกอุปกรณ์"

**Settings › Staff (เพิ่มจากเดิม):** ปุ่ม "เชิญ staff" (ชื่อ, อีเมล, แผนก, role) → ส่งอีเมลตั้งรหัส · สถานะ "รอตั้งรหัส / ใช้งาน / ปิดใช้งาน" · เมนู ⋯ : ส่งคำเชิญอีกครั้ง, บังคับออกจากระบบ, ปิดใช้งาน (ConfirmModal)

**session หมดอายุระหว่างใช้งาน:** แอปต่ออายุเงียบ ๆ · ต่อไม่ได้ → modal "หมดเวลาเข้าสู่ระบบ" ให้ login ใหม่ **โดยไม่เสียข้อความที่พิมพ์ค้างอยู่** (เก็บ draft ไว้ก่อน) แล้วกลับหน้าเดิม

## อัปเดต v11 — Realtime ทุกหน้า · Role กำหนดเอง

### Realtime ที่ผู้ใช้เห็น
- ทุกหน้าที่เปิดอยู่อัปเดตเองเมื่อมีคนอื่นเปลี่ยนข้อมูล (แท็ก, แผนก, role, staff, SLA, ลูกค้า, dashboard, แชท) — ไม่มีปุ่มรีเฟรช
- แถว/การ์ดที่เพิ่งเปลี่ยนมีพื้นไฮไลต์จาง ๆ 1.5 วินาที (reduced motion = ไม่มี) · ถ้ากำลังแก้ฟอร์มของข้อมูลนั้นอยู่ **ไม่เขียนทับ** แต่ขึ้นแถบ "{{name}} เพิ่งแก้ข้อมูลนี้ · [โหลดล่าสุด]"
- ข้อมูลที่เราไม่มีสิทธิ์แล้ว (ถูกย้ายแผนก/ถูกลบ) หายจากหน้าจอพร้อม toast อธิบาย
- สิทธิ์ของเราถูกเปลี่ยน → เมนู/ปุ่มปรับทันที + toast "สิทธิ์ของคุณถูกปรับโดยผู้ดูแลระบบ" · ถ้าหน้าที่เปิดอยู่ไม่มีสิทธิ์แล้ว → พาไปหน้าแรกที่เข้าได้
- สถานะการเชื่อมต่อ: หลุด > 3 วินาที → แถบบางด้านบน "กำลังเชื่อมต่อใหม่…" · ต่อได้ → หายเอง (ไม่รบกวนตอนปกติ)
- จุดออนไลน์ของ staff (เขียว/เทา) ใน dropdown มอบหมายและหน้า Staff

- สิทธิ์ที่พ่วงกัน (แก้ ⇒ ดู) ติ๊กให้อัตโนมัติ และปลดไม่ได้จนกว่าจะปลดตัวที่ต้องพึ่ง (tooltip อธิบาย)

- ผู้ใช้ไม่เห็นเลข bit — เห็นแค่ต้นไม้ติ๊ก (bitmask เป็นรายละเอียดฝั่งระบบ)

## อัปเดต v12 — Context Panel: ทุกอย่างของแชทที่เปิดอยู่ในแท็บขวามือ

แผงขวา (เดิม Customer Panel) กลายเป็น **Context Panel** ที่มีแท็บ · ทุกการตั้งค่า/จัดการของแชทที่เปิดอยู่ย้ายมาอยู่ที่นี่ · หัว thread เหลือแค่ข้อมูลสรุป → thread โล่ง อ่านง่าย · **Settings (แท็ก/แผนก/SLA/Roles/Staff) ยังเป็นหน้าในเมนูซ้ายเหมือนเดิม**

### หัว thread (เหลือเท่านี้)
```
ENQ-000123 · Bangkok Bistro Co.   [กำลังดำเนินการ]  เหลือ 0:06 ชม.      [แผงขวา ▸]
```
- กดชื่อลูกค้า → เปิดแท็บ "ลูกค้า" · กดสถานะ/SLA → เปิดแท็บ "เรื่อง"

### แท็บ
```
┌ [เรื่อง] [ลูกค้า ▲] [ไฟล์ 4] [ประวัติ] ────────────── [ปักหมุด] [×] ┐
```
| แท็บ | มีอะไร | สิทธิ์ |
|---|---|---|
| **เรื่อง** (ค่าเริ่มใน Inbox มุมมองเรื่อง) | ปุ่มลัด [รับเรื่อง] [รอลูกค้า] [แก้ไขแล้ว] · **สถานะ** (เลือกได้เฉพาะที่เปลี่ยนได้ตาม state machine) · **มอบหมาย** (dropdown staff + จุดออนไลน์) · **แผนก** (เปลี่ยน = ส่งต่อ → ConfirmModal + เหตุผล) · **ความเร่งด่วน** · **ประเภท/หัวข้อย่อย** · **สินค้า** · **แท็ก** · **SLA** (เป้า, กำหนดเสร็จ, เหลือ/เกิน, หยุดนับ, policy ที่ใช้) · ข้อมูลอ้างอิง (เลข ENQ [คัดลอก], ช่องทางแรก, สร้างเมื่อ, first response) | แต่ละช่องผูกสิทธิ์เดิม: `inbox.status.*`, `inbox.assign.*`, `inbox.tag.apply` + ใหม่ `inbox.enquiry.edit` (ความเร่งด่วน/ประเภท/สินค้า) · ไม่มีสิทธิ์แก้ = แสดงเป็นข้อความอ่านอย่างเดียว |

## อัปเดต v13 — สถานะ 6 ขั้น · เปิดใหม่อัตโนมัติ · เปลี่ยนได้เฉพาะผู้รับผิดชอบ

### ตัวเปลี่ยนสถานะ (Context Panel › เรื่อง)
```
สถานะ   OPEN ─ ASSIGNED ─ [IN PROGRESS] ─ WAITING ─ RESOLVED ─ CLOSED     ← stepper แสดงตำแหน่งปัจจุบัน
        [รอลูกค้า]  [แก้ไขแล้ว]                                          ← ปุ่มเฉพาะขั้นที่ไปต่อได้จากตรงนี้
```
- **เรื่องยังไม่ถูก assign:** แสดงแค่ [รับเรื่อง] (มี `ASSIGN_SELF`) หรือ [มอบหมาย…] (มี `ASSIGN_OTHERS`) · ปุ่มสถานะอื่นไม่แสดง + ข้อความ "มอบหมายผู้รับผิดชอบก่อนจึงเปลี่ยนสถานะได้"
- **ไม่ใช่ผู้รับผิดชอบและไม่มีสิทธิ์ `changeAny`:** stepper แสดงแบบอ่านอย่างเดียว + "เฉพาะ สมชาย (ผู้รับผิดชอบ) หรือหัวหน้าเท่านั้นที่เปลี่ยนสถานะได้"
- ผู้รับผิดชอบตอบข้อความแรก → ASSIGNED เปลี่ยนเป็น IN PROGRESS ให้เอง (toast แจ้ง)
- [แก้ไขแล้ว] → ขั้น RESOLVED + ปุ่ม [ยกเลิก] ใน toast 5 วิ · RESOLVED ไม่ปิดเองตามเวลา — ปิดเมื่อลูกค้ายืนยัน หรือกด [ปิดเรื่อง]
- เรื่องที่เปิดใหม่แต่เป็นคำถามอื่น → เลือกข้อความ (ติ๊กที่ bubble) แล้วกด [แยกเป็นเรื่องใหม่] → เลือกประเภท → ข้อความย้ายไปเรื่องใหม่ เรื่องเดิมกลับสถานะก่อนหน้า
- **ส่งต่อแผนก** และ **เปลี่ยนผู้รับผิดชอบ** อยู่ในช่องแผนก/มอบหมายเหมือนเดิม: ส่งต่อ → กลับเป็น OPEN ในแผนกใหม่ · เปลี่ยนคน → ASSIGNED
- มีคนเปลี่ยนไปก่อน (409) → "สถานะถูกเปลี่ยนเป็น RESOLVED โดยสมชายแล้ว" แล้ว stepper อัปเดต

### ป้ายเสริมบนรายการ/หัว thread
- **เปิดใหม่ (ครั้งที่ 2)** — ลูกค้าทักหลังแก้ไขแล้ว/ปิดแล้ว · ผู้รับผิดชอบเดิมได้แจ้งเตือน "Bangkok Bistro เปิดเรื่อง ENQ-000123 อีกครั้ง" และเรื่องขึ้นใน "ของฉัน"
- **ส่งต่อแล้ว** — เคยถูกส่งต่อแผนก (tooltip: จากแผนกไหน เมื่อไร)

```
[ยังไม่มีคนรับ 4] [OPEN 12] [ASSIGNED 5] [IN PROGRESS 20] [WAITING 7] [RESOLVED 31] [CLOSED]   [เปิดใหม่] [ส่งต่อแล้ว]
```
